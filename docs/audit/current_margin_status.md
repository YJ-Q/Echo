# 当前 Margin 状态审计

审计日期：2026-08-20。本文只描述可由仓库代码和测试复核的事实，不把设计目标写成现状。

## 代码已验证

- 工程采用 JavaScript ESM、Express、Electron 和 SQLite。
- `src/services/chatService.js` 负责编排输入分析、模型回复、项目/学习状态、用户画像和记忆写入。
- `src/storage/memoryStore.js` 同时承担 Schema、会话、记忆召回、学习、行动和运营数据职责，模块边界过宽。
- 当前 `conversations` 同时被用于会话历史和可长期召回内容，尚未严格区分 Pi Session 与 Margin 长期记忆。
- operation proposal/confirmation 已支持先提议、再确认的可逆操作路径；`operationExecutor.js` 当前拒绝破坏性删除。
- 现有接口仍是兼容路径。本阶段没有改动 `chatService.js`，也没有把 Pi 接入用户聊天主链路。

## 测试已验证

阶段 0 开始前执行 `npm test`，基线为 186 个测试通过、0 个失败。该数字只证明既有自动化检查通过，不等于跨会话用户价值、市场需求或任务成功率。

新增阶段 0 测试验证版本契约、安装审计、runtime bootstrap、工具白名单和审计文档。测试数量应以每次运行日志为准，不在材料中预写最终数字。

## 设计目标而非现状

Margin 的目标是把 Pi 的 Session/分支/压缩运行历史与 Margin 的结构化项目状态、任务、决策、记忆、事件和行动分层。当前仓库尚未集成 Pi 到生产聊天链路；阶段 0 只有隔离 SDK spike。因此在真实跨 Session MVP、评测和用户研究完成前，不得在简历中声称“已完成基于 Pi 的连续性 Agent”。

## 已知风险

- 普通聊天可能污染学习或项目状态。
- 旧记忆可能覆盖新状态，现有访问强化可能造成重复召回正反馈。
- 会话历史、压缩摘要和长期记忆语义仍需拆分。
- 删除、更正、敏感信息确认和工具越权控制尚未形成完整闭环。
